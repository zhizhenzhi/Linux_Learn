2.2 系统调用
系统调用是操作系统内核提供给应用程序
open() read write close exit _exit()


子进程通过close()释放文件描述符之后,父进程对于相同的文件描述符执行write操作仍然成功了,这是为什么？
struct file结构体中有一个属性为引用计数,记录的是与当前绑定的文件描述符数量,close()系统调用的作用是将当前进程中的文件描述符与对应的结构体解绑,使得引用计数减1,当变为0时,才会释放其所有资源

5.3 PCb
内核会保存每个进程的一些信息,称为进程控制块PCB,内容如下:
进程编号PID;进程状态信息;进程切换时需要保存和恢复的一些CPU寄存器,关键的有程序计数器;内存管理信息;当前工作目录;进程调度信息(进程优先级);IO状态信息;同步和通信信息;用户id和组id
5.4进程的内存模型
文本(程序代码),初始化数据(已经赋值全局变量和静态变量),未初始化数据BSS(没有初始化的全局变量和静态变量),堆(存放动态分配的内存)->未分配内存<-栈(存放局部变量,函数参数,返回地址等部分),argv environ(存放程序参数和环境变量),内核空间kernel space
5.4.2栈帧:程序调用函数时用于存储函数调用和局部变量的一块内存,每次函数调用时,都会在调用者的栈上创建一个新栈帧,这个栈帧包含了函数的返回地址,参数,局部变量等
内核空间:进程虚拟内存中保留给操作系统内核的部分,用于存放内核代码和数据
用户空间:内存中分配给1用户程序的部分,与内核空间隔离

5.5进程的状态
5.5.1CPU的虚拟化
理论上,同一时刻单核只能运行一个进程,但所实际不是,这是因为CPU调度单元对Cpu的资源做了时间分片,即在时间尺度上对CPU做了划分,实际上进程间的切换非常迅速
5.5.2CPU调度
进程执行到某一时刻,被内核中断,然后重新开始之前中断的进程,这种决策就是调度,是由调度器的代码处理的
进程的调度是通过时钟中断实现的
5.5.3抽象的进程状态模型:初始态,就绪态,运行态,阻塞态,终止态,僵尸态
5.5.4 linux进程状态实现:D不可中断睡眠状态  I空闲的内核线程 R运行或可运行状态(就绪运行态   S可中断睡眠状态 T由工作控制信号停止 t由调试器停止的状态 Z僵尸态 DSTt阻塞态

5.7异常和中断
内核态:CPU的一种运行模式,具有执行所有指令和访问所有硬件资源的权限
用户态
中断异常区别:中断处理被调用时,CPU会清除EFLAGS寄存器中的IF(interrupt enable)位,避免其他中断执行,而异常被调用时IF不被清除

5.8进程创建过程
内核启动时会创建1号进程(systemd)和2号内核线程(kthreadd),其他进程全部由systemd及其子进程通过fork()+execve的方式创建,其他内核线程都是由kthreadd及其创建的内核线程通过kthread_create()这样的方式创建的。fork()和kthread_create()是通过创建系统调用clone()实现的

fork:写时复制机制可以提高进程创建效率,子进程完整复制了父进程的地址空间,此时父子进程的虚拟内存空间映射到相同的物理内存空间。只有当二者之一执行了写入操作才会复制写入区域的内容,为父子进程维护不同的物理页帧

5.8.4进程组:在UNIX和类UNIX系统中用来标识一个或多个进程的集合
